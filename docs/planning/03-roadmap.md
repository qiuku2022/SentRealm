# 产品路线图

> **权威范围**仍以 [产品定义与 MVP](./01-product-definition-and-mvp.md) 为准。本文档回答：**做到哪一步了、下一步做什么、依赖与风险是什么**。  
> 版本变更明细见根目录 [CHANGELOG.md](../../CHANGELOG.md)。技术待决项见 [架构待定 ADR](../architecture/README.md#待定--后续-adr)。

**文档日期**：2026-07-17  
**当前对外状态**：Phase 1 MVP 核心已完成（M2 / `0.2.0`）；**尚无**面向终端用户的 Windows 安装包（待 ADR-008）。

```text

     ✅ 已完成              ✅ 已完成              🔜 下一目标         📋 规划中
```

## 2. 已完成（M1 / M2）

### M1 — Phase 0 脚手架

| 交付 | 说明 |
|------|------|
| 四模块骨架 | `core` / `cli` / `gui` / `mcp`（[ADR-007](../architecture/adr/007-multi-entry-modules.md)） |
| Tauri ↔ FastAPI | 本机 `127.0.0.1:17300`，health 就绪（[ADR-006](../architecture/adr/006-tauri-spawn-fastapi.md)） |
| Settings + SQLite | 三入口共用配置（[ADR-004](../architecture/adr/004-sqlite-user-settings.md)） |
| 契约 | OpenAPI、`cli-mcp.md`；preprocess 可为 stub |

### M2 — Phase 1 MVP 核心

| 交付 | 说明 |
|------|------|
| 8 步流水线 | 去标点 → 空格 → 检测 → 规则断句 → … → LLM 发送池（可选）→ 标记 |
| 字词表规则断句 | 禁止硬切；数据在 `break_lexicon/` |
| LLM 发送池 | 批 ≤10；质检（长短 + 句意守恒）；每行最多 3 次返工（[产品定义](./01-product-definition-and-mvp.md#llm-发送池与质检返工)、[ADR-005](../architecture/adr/005-llm-integration-privacy.md)） |
| GUI 核心 | 输入 / 参数 / 对照预览 / 超长高亮 / 复制 |
| 多入口一致 | 相同 Settings + 文稿 → gui/cli/mcp 结果一致 |
| 隐私边界 | LLM 仅池内超长行；密钥环境变量（[ADR-005](../architecture/adr/005-llm-integration-privacy.md)） |

**M2 成功标准**（与产品定义对齐，验收时核对）：

1. 定稿口播稿处理后，剪映文稿匹配「大致可用」
2. 常规篇幅秒级完成
3. 横屏 15 / 竖屏 10 开箱可用，自定义字数可预期
4. 写稿方可直接把结果交给剪辑粘贴

## 3. 下一优先：M3 — 可分发 MVP（目标 `1.0.0`）

目标：让**不熟悉本仓库**的写稿/剪辑同学，能安装并完成「粘贴 → 处理 → 复制 → 剪映」主流程。

### 3.1 必须完成（阻塞 1.0）

| 项 | 说明 | 依赖 |
|----|------|------|
| **ADR-008 生产打包** | ✅ 已接受：PyInstaller sidecar（见 [ADR-008](../architecture/adr/008-production-packaging.md)） | — |
| **Windows 安装包** | ✅ 可本地构建（`scripts/build_installer.ps1`）；干净机冒烟与对外分发仍待完成 | ADR-008 实现 |
| **冒烟验收清单** | 干净机器：安装 → 打开 → 处理样例稿 → 复制 → 剪映粘贴 | 安装包 |
| **用户手册同步** | [docs/user/](../user/README.md) 与安装后实际 UI 一致 | GUI 定稿 |
| **CHANGELOG 发版条目** | `Unreleased` → `1.0.0` + 日期 | 发版流程 |

### 3.2 强烈建议（不阻塞技术发版，但影响体验）

| 项 | 说明 |
|----|------|
| 首次启动引导 | 横/竖屏预设说明、与剪映的衔接一句提示 |
| 后端失败可读提示 | 「后端未就绪 / 端口占用」对应处理（与 [running-locally](../dev/running-locally.md) FAQ 同源，面向用户改写） |
| LLM 配置向导（可选） | 未配置时明确提示「将跳过语义断句，仅规则+标记」 |
| 工作区持久化打磨 | 若已落地 [ADR-010](../architecture/adr/010-workspace-document-persistence.md)：自动保存、活动项修复、删除确认文案 |

### 3.3 明确不做（仍属产品非目标）

- 对接剪映开放 API / 自动写入工程
- SRT/ASS 导出、ASR、云端同步、多用户权限
- 改写/润色文稿内容

（完整列表见产品定义「不包含」。）

### 3.4 M3 完成定义（DoD）

- [ ] 干净 Windows 10/11 上安装后，无需开发环境即可完成主流程
- [ ] 关闭应用后无残留 uvicorn（或有文档化的清理方式）
- [ ] 默认配置下：无 LLM 密钥也能完成去标点 + 规则断句 + 标记
- [ ] 用户手册与 CHANGELOG `1.0.0` 已更新
- [ ] `uv run pytest`（默认集）在发版分支通过

## 4. M4 与二期方向（规划，未排期）

以下来自产品定义「后续可扩展」与架构占位，**不承诺版本号与日期**。立项时再拆任务。

### 4.1 产品增强（M4 候选）

| 方向 | 价值 | 备注 |
|------|------|------|
| 断点字词表持续扩充 | 减少标记行、提高剪映一次通过率 | 随真实文稿迭代；配套回归测试 |
| 工作区 / 多文稿体验 | 项目侧栏、历史结果、备份心智 | 对齐 ADR-010；cli/mcp 项目管理非必须 |
| 批量处理 | 多文件管道 | 产品定义标为非 MVP |
| 纯离线模式产品化 | 无 LLM 时的能力说明与 UI 状态 | 技术上 M2 已可跳过 LLM |
| SRT 导出 / 校对辅助 | 剪辑下游 | 需单独产品设计 |

### 4.2 工程与平台

| 项 | 触发条件 | 说明 |
|----|----------|------|
| **ADR-009** uv workspace 物理拆包 | 流水线与依赖稳定 | 多包发布、边界更清晰 |
| macOS / Linux | 有明确用户需求 | `default_config_path` / 工作区路径、WebView 前置 |
| MCP settings / CLI `config` | 二期 | 当前仅 gui 写 Settings |
| CI 强化 | 发版前 | 前端 lint/test、打包冒烟 |

### 4.3 远期（二期+）

- 全文 LLM 断句（相对「仅超长行」）
- 更多字幕工具预设（非仅剪映）
- 历史记录、多设备同步（若做，需重开隐私与存储 ADR）

| 依赖 | 说明 |
|------|------|
| M3 ← ADR-008 | 无打包方案则无法向非开发者交付 |
| 用户手册 ← 实际 GUI | UI 文案/布局变更须回写 `docs/user/` |
| 词表质量 ← 真实样例 | 需收集口播稿样例（脱敏）做回归 |
| LLM 体验 ← 用户自备 API | 产品不捆绑密钥；文档须写清「可选」 |

## 6. 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| **Python 运行时打包体积/兼容性** | 安装包大、杀软误报、路径问题 | ADR-008 早做 spike；限定 Win10/11 x64 |
| **字词表覆盖不足** | 标记行偏多，剪映仍需手改 | 黄金样例 + 持续扩充；UI 明确提示人工改标记行 |
| **剪映版本行为差异** | 「最佳实践」漂移 | 文档注明以用户本地剪映为准；不承诺 100% 零微调 |
| **LLM 不稳定 / 费用** | 断句质量波动、返工增调用 | 默认关闭；质检硬门禁；满 3 次标记；每批 ≤10 行 |
| **端口 17300 冲突** | 应用起不来 | 安装包检测与可读错误；长期可评估换端口策略（需改 ADR-006） |
| **文档与代码漂移** | 手册不可信 | 发版 DoD 含文档核对；API 变更同步 openapi |

## 7. 近期建议工作序（给执行用）

按优先级，**不**表示已排期：

1. 按 [ADR-008](../architecture/adr/008-production-packaging.md) **实现** sidecar `.spec`、binaries 脚本与 Rust 生产 spawn 分支
2. 打出 **首个内部安装包**，在干净机上跑主流程冒烟
3. 对照实机 UI **修订用户手册**（安装步骤、按钮文案）
4. 词表与标记行：收集 3～5 篇真实口播样例做回归
5. 准备 `1.0.0`：CHANGELOG、版本号、验收勾选 M3 DoD
6. 发版或重大迭代前按 [implementation-status.md](../dev/implementation-status.md) 做实现对照
