# 产品定义与 MVP

> **权威来源**：产品范围与 MVP 边界以本文档为准。

## 产品定位

SentRealm 是一款面向视频创作者的**文稿预处理工具**，用于在将文本粘贴到剪映「文稿匹配」之前，自动完成去标点、智能断句与分行。

剪映文稿匹配若直接粘贴原始文稿，常见问题包括：字幕轨残留标点符号、单条字幕过长。人工在剪映内逐条调整耗时。SentRealm 将「写好并确认的口播/解说稿」转换为剪映友好的格式，粘贴后字幕基本可用，仅需少量微调。

**产品形态**：本地桌面应用（Tauri 2 + React 前端 + Python 后端），文稿在本地处理，不上传云端。

## 目标用户

经常制作**口播、解说、采访类**视频，并使用剪映「文稿匹配」功能生成字幕的内容创作者及协作团队，典型包括：

- 撰写口播/解说稿的内容作者
- 将定稿文稿交给剪辑部门对接剪映的协作流程中的写稿方或统筹方
- 在剪映中执行文稿匹配的剪辑人员（间接受益：收到预处理稿，减少字幕返工）

**文稿来源**：手写文稿，经负责人确认后流转至剪辑部门——非实时 ASR 转写场景为主。

## 核心场景

### 主流程

1. 用户将定稿长文稿粘贴到 SentRealm（或导入文本文件）
2. 选择处理参数（横屏/竖屏预设，或自定义单行最大字数）
3. 一键处理，预览处理结果（原文 vs 处理后对照）
4. 复制处理后的文本
5. 粘贴到剪映「文稿匹配」，生成字幕
6. 在剪映内微调少量不匹配项（如有）

### 用户价值

| 痛点 | SentRealm 做法 |
|------|----------------|
| 字幕带标点 | 自动去除或规范化标点 |
| 单条字幕过长 | 按最大字数与语义断句，一行一句 |
| 人工逐条改字幕费时 | 预处理一次，剪映内基本不用再调 |

## 处理规则（产品约束）

输出文本须符合剪映文稿匹配的常见最佳实践（以用户本地剪映版本为准）：

- **去标点并保留边界**：句末标点形成自然句边界；逗号、分号、顿号等仅记录为超长时的候选断点；引号、括号只删除；保留的符号（如 `%` `％`）不删除
- **空格规范化**：仅保留英文词间、英文与中文之间的空格；其余空格去除；空格不计入字数
- **一行一句**：每行对应剪映匹配后的一条字幕；**不允许空行**
- **长度可控**：规则层尽量满足用户上限；无法自然切开的局部超长行保留并标记，不以破坏语法的硬切换取“零标记”

### 字数计数

字幕在屏幕上占宽，中英文与数字均占空间，故**计字数时不区分中英文**：

| 字符类型 | 计数 |
|----------|------|
| 中文汉字 | 1 字 |
| 英文字母 | 1 字 |
| 数字 | 1 字 |
| 标点 | 不计入；按去标点规则去除（默认保留 `%` `％`） |
| 空格 | 不计入字数；见下方「空格规则」 |

断句与「单行最大字数」校验仅统计中文、英文字母、数字。行与行之间不得出现空行。

### 空格规则

| 场景 | 处理 |
|------|------|
| 两个英文单词之间 | **保留**一个空格，如 `Hello world` |
| 英文与中文之间 | **保留**一个空格，如 `使用 iPhone 拍摄`、`AI 技术` |
| 数字与英文之间 | **保留**一个空格，如 `iPhone 15` |
| 数字与中文之间 | **无空格**，如 `2024年`；若原文有空格则去除 |
| 数字与 `%` / `％` 之间 | **无空格**，如 `增长50%`、`增长50％` |
| 中文与中文之间 | 无空格（原本不应出现） |
| 首尾空格、多余连续空格 | **去除** |
| 因去标点产生的孤立空格 | **去除** |

空格不参与单行最大字数的计数，但保留的空格会占用屏幕宽度——断句时应将保留的空格计入**显示宽度**评估（Phase 1 可按「字数 + 保留空格数」估算行宽，或按渲染效果校验；实现边界见 [data-flow.md](../architecture/data-flow.md)）。

### 单行最大字数

| 预设 | 默认最大字数 | 说明 |
|------|--------------|------|
| 横屏 | 15 字 | 适合横屏视频字幕宽度 |
| 竖屏 | 10 字 | 适合竖屏/短视频字幕宽度 |
| 自定义 | 用户指定 | 覆盖上述预设 |

用户可在横屏/竖屏预设与自定义字数之间切换；当前上限同时作为自动断句目标与最终超长标记阈值。

### 去标点规则

**默认去除**的符号：

| 类别 | 符号 |
|------|------|
| 全角标点 | `，` `。` `！` `？` `：` `；` `——` `、` |
| 半角标点 | `,` `.` `!` `?` `;` `:` |
| 引号 | `“` `”` `‘` `’` `"` `'` |
| 括号 | `（` `）` `(` `)` |
| 其他 | `…` |

去除时按内置边界等级处理：

| 边界等级 | 默认符号 | 行为 |
|----------|----------|------|
| **硬边界** | 原始换行、`。` `！` `？` `.` `!` `?` | 结束当前自然句；短自然句允许保留，不与下一句强行合并 |
| **强候选** | `，` `,` `；` `;` `：` `:` | 仅当所在自然句超长时，作为优先断点参与全局选点 |
| **普通候选** | `、` `——` `…` | 仅当所在自然句超长时，作为较低优先级断点 |
| **仅删除** | 引号、括号 | 删除但不产生断点 |

因此，引号中的短词不会因开闭引号被孤立成行；未超长自然句中的逗号也不会自动换行。

**默认保留**（不删除、不换行）：

| 符号 | 说明 |
|------|------|
| `%` | 半角百分号，如 `增长50%` |
| `％` | 全角百分号，与 `%` 同等处理 |

**可自定义**：用户可配置「去除」与「保留」的符号集合，例如：

- **增加去除项**：如上表未覆盖的符号；未知自定义符号默认只删除、不产生断点
- **增加保留项**：如 `+`、`-`；或覆盖默认保留（若用户明确不要 `%` / `％`）
- **从默认去除列表中移除**：该符号不再删除；`punctuation_keep` 与去除列表冲突时以保留为准

规则以配置形式保存，**持久化到本地 SQLite**（gui、cli、mcp 共用同一库；见 [ADR-004](../architecture/adr/004-sqlite-user-settings.md)）。`POST /api/v1/preprocess` 请求体中的 `settings` 可仅覆盖当次处理，不写库。

### 断句处理流程

处理按以下流水线顺序执行；每一「检测字数」步骤均校验**每一行**是否超过当前设定的单行最大字数。

```
识别标点边界并去标点 → 空格规范化
    ↓
按硬边界得到自然句并检测字数
    ↓
超出限制的自然句 → 候选边界 + 字词表全局断句 → 短行修复
    ↓
检测每行字数
    ↓
仍超出的行 → 入 LLM 发送池（未配置 API 时跳过，直接标记）
    ↓
分批（最多 10 行）→ LLM 断句 → 结果写回原位
    ↓
质检不合格 → 回池返工（每行最多 3 次，含首次）→ 仍失败则放弃
    ↓
检测每行字数 → 仍不合格的行 → 标记（不再自动处理）
```

| 步骤 | 说明 |
|------|------|
| 1. 识别边界并去标点 | 按硬边界、强候选、普通候选、仅删除四类处理；保留的符号（如 `%` `％`）留在原位 |
| 2. 空格规范化 | 保留英文词间、英中文之间空格；去除其余空格 |
| 3. 检测字数 | 按硬边界形成自然句，统计字数（中文、英文、数字各计 1 字）；合并空行 |
| 4. 规则断句 | 仅对**超出字数限制**的自然句，在候选标点、英文词界与字词表断点间做全局选点，并回并可安全合并的短行 |
| 5. 检测字数 | 同上 |
| 6. LLM 发送池断句 | 将规则后**仍超长**的行入池；按批调用 LLM；质检与返工见 [LLM 发送池与质检返工](#llm-发送池与质检返工) |
| 7. 检测字数 | 同上 |
| 8. 标记 | 放弃 LLM 或仍不合格的行，在预览中**标记**，不再自动处理，由用户人工调整 |

**示例（步骤 1）**

原文：

```
大家好，欢迎来到今天的节目。今天我们聊聊 AI 技术。
```

去标点并识别边界后（横屏默认 15 字）：

```
大家好欢迎来到今天的节目
今天我们聊聊 AI 技术
```

**标记行**：输出文本中保留该行内容，但在 UI 中醒目标出，提示用户复制前需留意或手动修改。入发送池**不是**最终标记；最终标记仅发生在步骤 8。

**LLM 使用范围**：非全文处理；仅规则断句后仍超长的行。需用户配置 LLM API（密钥经环境变量 `SENTREALM_LLM_API_KEY` 提供，endpoint/model 存 SQLite；**不上传全文**，仅发送池内超长行，每批最多 10 行）。调用范围与隐私边界见 [ADR-005](../architecture/adr/005-llm-integration-privacy.md)。

**LLM 未配置时**：跳过步骤 6，规则断句后仍超长的行直接进入步骤 8 标记。

### 规则断句细则

适用于步骤 4：第一步完成标点分类与删除后，某个自然句仍超过单行最大字数时，由规则引擎尝试切分。

| 规则 | 说明 |
|------|------|
| **禁止硬切** | 不允许在任意字位按字数强行切断；仅在**允许的断点**处切分 |
| **允许断点** | 来自强/普通标点候选、英文词界与字词表（见 [允许断点字词表](#允许断点字词表)） |
| **英文词界** | 禁止在两个英文单词之间切断（即不可把 `Hello world` 切成 `Hello wo` / `rld`）；应在英文词之间的空格处切分 |
| **最短段长** | 自动规则切分得到的各段须 `≥ min_chars`。`min_chars` 默认 `5`，须 `1 ≤ min_chars ≤ max_chars`；完整自然句本身较短时不受此限 |
| **完整规划** | 在一个自然句内全局选择整组切点；允许把无法自然切开的局部超长段保留并标记，避免一个难点拖累整句或产生“短头 + 超长尾” |
| **短行修复** | 对低于建议长度且与相邻段合并后不超限的片段回并；不跨越原始换行或句末硬边界 |
| **质量取舍** | 逗号等原始标点优先，整词/英文词界其次，单字切点最低；宁可保留超长标记，也不使用明显破坏语法的切点 |

规则断句后仍超长的行（含**完全无合法切点**而整行保留、以及**切分后仍有超长段**），进入步骤 6 发送池；LLM 路径耗尽后仍不合格的，标记为超长行。

### LLM 发送池与质检返工

适用于步骤 6。目标：规则切不干净的超长行，经 LLM **只做断句、不改写**，按语义 / 语法 / 口播习惯切分；**不**以 LLM 结果每行严格落在 min～max 为硬目标（该约束仅适用于规则断句）。

#### 入池

| 项 | 约定 |
|----|------|
| 入池条件 | 步骤 5 之后，字数仍 `> max_chars` 的行 |
| 池条目 | 保存原文行文本、在全文中的锚点（写回位置）、已尝试次数（初始 0） |
| 批大小 | **最多 10 行**一批；不足 10 亦立即发送（不无限等待凑满） |
| 未配置 LLM | 不入池，直接步骤 8 标记 |

#### 批量调用与写回

1. 从池中取出至多 10 条，**一次请求**发给 LLM（可在同请求内按序号区分各行）。
2. LLM 对每一条返回切分后的多行文本；流水线将结果**写回该行原锚点**（原一行替换为多行，后续行顺延）。
3. 对每条结果做 [质检](#llm-断句质检)；合格则完成该条目；不合格则见返工。

#### LLM 断句质检

切分结果须**同时**满足：

| 检查 | 通过条件 |
|------|----------|
| **句意守恒** | 将结果行按序拼接（去掉行间换行，行首尾空白 trim 后连接）得到的字符序列，与入池原文（同样 trim）**完全一致**；禁止增删改用词 |
| **有效切分** | 至少 **2** 行非空结果（单段视为未切分） |
| **有进展** | 最长结果行的 countable 字数 **小于** 入池原文（防止假切分） |
| **阅读节奏** | 由提示词约束「意群 / 语法 / 口播习惯」；`max_chars` 在 prompt 中为**参考上限**（尽量不超过，语义需要可略超）；MVP **不做**额外 NLP 打分 |

**不**在 LLM 质检中校验 `min_chars` / 每行 `≤ max_chars`（该硬门禁仅用于规则断句）。步骤 8 仍对**最终**全文 `> max_chars` 的行标记。

任一项失败 → 该条目质检不合格。

#### 返工与放弃

| 项 | 约定 |
|----|------|
| 返工 | 质检不合格（或该次 API 调用失败）时，**尝试次数 +1**，条目连同**原始入池文本**重新入池 |
| 上限 | 每条最多 **3 次** LLM 处理（含首次）；达到上限仍不合格 → **放弃自动处理** |
| 放弃后 | 保留入池时的原文行（未采用不合格切分），进入步骤 8 **标记** |
| 传输层重试 | 单次 HTTP 调用的网络/超时/5xx 短重视重试见 [ADR-005](../architecture/adr/005-llm-integration-privacy.md)；与上文「质量返工次数」分开计数，但 API 最终失败仍消耗 1 次质量尝试 |

### 允许断点字词表

除标点候选与英文词界外，规则断句仅使用下列字词表位置；找不到合规切点时保留局部超长行，禁止硬切。

**运行时词表**来自 SQLite `Settings.break_lexicon`（gui / cli / mcp 共用）；**出厂默认**与「恢复默认」来自打包 `packages/core/src/sentrealm_core/data/break_lexicon/*.txt`，由 `pipeline/break_lexicon.py` 加载。

| 类别 | 文件 / Settings 字段 | 含义 | 示例 |
|------|----------------------|------|------|
| **受保护词** | `protected_words` | 禁止从中切断（最长 4 字）；高频否定/情态组合整体保留 | `就业`、`重要`、`不可能`、`未必能够` |
| **后可断** | `break_after_words` | 整词结束后可换行 | `所以`、`但是`、`然后`、`其实` |
| **后可断（单字）** | `break_after_chars` | 单字结束后可换行，作为低优先级兜底 | `了`、`吗`、`呢`、`吧` |
| **前可断** | `break_before_words` | 整词开始前可换行；包含通用高频谓语起点 | `在`、`对于`、`可能`、`需要`、`仍然`、`通常` |

**GUI**：底部 FAB「编辑规则」可编辑上述四类并保存至本机配置；左下「恢复默认」读内置 txt，须点保存才生效。

另：**英文词间空格**后始终允许切分。

选点策略：使用全局动态规划，在整句范围综合边界等级、行长均衡、短行惩罚与局部超长惩罚。历史或用户词表中的 `的`、`地`、`得`、`着`、`有`、`也`、`还`、`就`、`又`、`到` 以及 `非常` 后切点属于高风险位置，仅在两侧都足够完整时才可能采用。算法决策见 [ADR-012](../architecture/adr/012-natural-boundary-segmentation.md)。

## MVP 范围

### 包含

- 文稿输入：文本框粘贴、`.txt` 文件导入
- 文稿预处理（按 [断句处理流程](#断句处理流程)）：
  - 标点分级、去除与候选边界记录（默认保留 `%` `％`；支持自定义保留/去除规则）
  - 空格规范化
  - 多轮字数检测
  - 规则断句（仅处理超长行；禁止硬切；字词表驱动）
  - LLM 发送池断句（规则后仍超长的行入池；每批最多 10 行；质检 + 最多 3 次返工；不改写内容；未配置 API 时跳过）
  - 超长行标记（放弃或最终仍不合格的行在预览中标注，不再自动处理）
  - 输出无空行（每行均有内容，标记行除外仍占一行）
- 参数配置：
  - 横屏（15 字）/ 竖屏（10 字）预设
  - 自定义单行最大字数
  - 去标点保留/去除规则自定义
  - LLM API 配置（端点、模型等）
- 结果预览：原文与处理后对照、行数统计、**超长标记行**高亮
- 一键复制到剪贴板
- 本地桌面应用；文稿本地处理；LLM 断句步骤需联网调用已配置的 API

### 不包含（非目标）

- 对接剪映 API 或自动写入剪映项目（剪映无开放接口；交付物为可复制文本）
- 视频时间轴对齐、SRT/ASS 字幕文件导出（后续版本可考虑）
- 改写文稿内容、润色、纠错（仅做格式与断句，不改语义）
- 实时语音转写（ASR）集成
- 多用户协作、云端同步、权限管理
- 批量处理多个文件（MVP 单篇处理即可）

### 后续可扩展（非 MVP）

- 全文 LLM 断句（当前 MVP 仅对规则后仍超长的行入发送池调用 LLM）
- 批量处理、历史记录
- 更多平台预设（除剪映外的字幕工具）
- SRT 导出与剪映字幕校对辅助
- 无 LLM 时的纯离线模式（仅规则断句 + 标记）

## 成功标准

MVP 视为达标，当满足以下条件：

1. **可用性**：定稿口播/解说稿经处理后，粘贴剪映文稿匹配，字幕**大致没问题**——绝大多数条目无需调整长度或去除标点
2. **效率**：处理耗时明显低于在剪映内人工逐条改字幕（目标：秒级完成常规篇幅文稿）
3. **可控性**：横屏 15 字、竖屏 10 字预设开箱可用；自定义字数生效且结果可预期
4. **协作友好**：写稿方处理后的文本可直接交给剪辑部门粘贴使用，无需二次说明格式要求

不要求 100% 零微调；允许极少量因口误、语速与文稿不完全一致导致的剪映内修正。

## 术语

| 术语 | 含义 |
|------|------|
| 文稿匹配 | 剪映「文本 → 智能字幕 → 文稿匹配」功能，根据粘贴文本与视频语音对齐生成字幕 |
| 单行 / 一行 | 处理后文本中的一行，对应剪映中的一条字幕 |
| 最大字数 | 单行允许的最大字符数；中文、英文字母、数字各计 1 字；空格不计入字数 |
| 空格规则 | 保留：英文词间、英中文间、数字英文间；无空格：数字中文间、数字与 `%`/`％` 间；去除其余多余空格 |
| 去标点规则 | 默认去除全角/半角标点、引号、括号、`…`；句末符号为硬边界，逗号等为超长时候选，引号/括号仅删除；默认保留 `%` `％` |
| 标记行 | 经规则与 LLM 发送池（含质检返工耗尽）后仍不合格或放弃的行；在预览中标注，不再自动处理 |
| 规则断句 | 超长行在允许断点处切分；禁止硬切；禁止切断英文单词；左右段均 ≥ min_chars |
| 允许断点字词表 | 规则断句切点定义；持久化 `Settings.break_lexicon`；出厂默认见 `data/break_lexicon/`；GUI「编辑规则」 |
| LLM 发送池 | 规则后仍超长行的待处理队列；每批最多 10 行送 LLM；详见 [#llm-发送池与质检返工](#llm-发送池与质检返工) |
| LLM 断句 | 对池内超长行做语义切分，不改写文稿用词；须通过句意守恒 + 有效切分 + 有进展质检；最终仍 `> max_chars` 的行由步骤 8 标记 |
| min_chars | 规则断句单行最短字数（设置可编辑，默认 5，须 ≤ max_chars） |
