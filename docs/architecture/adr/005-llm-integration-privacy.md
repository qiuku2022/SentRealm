# ADR-005: LLM 集成与隐私边界

## 状态

已接受（2026-07-19 修订：发送池批量、质检返工）

## 背景

根据 [产品定义](../../planning/01-product-definition-and-mvp.md)，预处理流水线在规则断句后，对**仍超出单行最大字数**的行经 **LLM 发送池**做语义切分，**不改写文稿用词**，并做句意守恒 + 有效切分质检；不合格可返工，每行最多 3 次。LLM 为**可选**能力：未配置 API 时跳过该步骤，超长行进入标记。

[ADR-004](./004-sqlite-user-settings.md) 规定：`llm_enabled`、`llm_endpoint`、`llm_model` 存 SQLite；**API 密钥不入库**，经环境变量提供。

需明确：客户端技术选型、发送池与批量请求、质检返工、mock 策略、传输层超时重试与隐私边界，供 `core` 中 `LlmClient` 与 `pipeline/llm_break.py` 实现。

## 选项

### A. 各厂商独立 SDK

分别集成 OpenAI、Anthropic、国内厂商 SDK。

- 优点：可用厂商特有能力
- 缺点：依赖多、适配成本高；MVP 过度

### B. OpenAI 兼容客户端（本决策选中）

使用 `openai` Python 包，通过 `base_url` + `api_key` 对接 OpenAI 及兼容端点（含多数国内 API 网关）。

- 优点：生态成熟；配置与 ADR-004 的 endpoint/model 字段自然对齐
- 缺点：非 OpenAI 兼容端点需另适配或网关转换

### C. LiteLLM 统一层

通过 LiteLLM 抽象多厂商。

- 优点：多模型统一接口
- 缺点：MVP 多一层依赖；调试路径更长

### D. 原始 httpx 调 REST

手写 HTTP 请求。

- 优点：依赖最少
- 缺点：需自行处理流式、错误格式、重试；维护成本高

## 决策

### 客户端架构

采用 **选项 B**，在 `core` 内定义 **`LlmClient` 协议**：

```python
# 概念示意
class LlmClient(Protocol):
    def break_lines(self, lines: list[str], max_chars: int) -> list[list[str]]: ...
```

| 方法 | 语义 |
|------|------|
| `break_lines` | 一次处理一批（1～10 条）超长行；返回与入参等长的「每条对应切分行列表」 |

兼容说明：若实现仍提供单行 `break_line`，流水线应以 `break_lines([line], …)` 为编排入口。

| 实现 | 用途 |
|------|------|
| `OpenAILlmClient` | 生产：使用 `openai` 包，`base_url` 取自 Settings，`api_key` 取自环境变量 |
| `MockLlmClient` | 测试：**依赖注入**，单元测试不访问网络、不依赖真实密钥 |

**不采用**全局环境变量开关 mock（如 `SENTREALM_LLM_MOCK=1`）；无密钥时通过「未配置 LLM」跳过步骤 6，而非静默 mock。

### 配置来源

| 项 | 来源 |
|----|------|
| `llm_enabled` | SQLite（ADR-004） |
| `llm_endpoint` | SQLite（ADR-004） |
| `llm_model` | SQLite（ADR-004） |
| API 密钥 | 环境变量 **`SENTREALM_LLM_API_KEY`** |
| `.env` | 本地开发可用；仓库根目录 `.env.example` 提供占位（`SENTREALM_LLM_API_KEY=`），实际 `.env` **不入 git** |

**启用 LLM 步骤的条件**：`llm_enabled == true`，且 `llm_endpoint`、`llm_model` 均已配置，**且** 环境变量中存在有效 API 密钥。任一不满足则跳过 LLM 断句（与产品定义、OpenAPI `Settings.llm_enabled` 说明一致）。

### 发送池与批量调用

编排在 `pipeline/llm_break.py`（或等价模块），须符合产品定义 [LLM 发送池与质检返工](../../planning/01-product-definition-and-mvp.md#llm-发送池与质检返工)：

| 项 | 约定 |
|----|------|
| 入池 | 规则断句后仍 `> max_chars` 的行（含无切点整行保留、切后仍超长） |
| 批大小 | 每批最多 **10** 条；池中不足 10 也发送 |
| 写回 | 将合格切分结果替换原锚点行 |
| 质检 | 句意守恒 + 有效切分（≥2 段）+ 有进展 + 每段 `≥ min_chars`；阅读节奏与 `max_chars` 参考上限靠提示词；不将 `max_chars` 作为硬门禁 |
| 质量返工 | 不合格或 API 最终失败 → 尝试次数 +1 后回池；**每行最多 3 次**（含首次） |
| 放弃 | 达上限仍不合格 → 保留入池原文，交步骤 8 标记 |

进度上报（如 SSE `llm_current` / `llm_total`）：以「入池条目的处理次数或已完结条目」为口径，须在实现与 [openapi](../../api/openapi.yaml) 说明中保持一致；推荐 `llm_total` = 首次入池条数，`llm_current` = 已终态（合格或放弃）条数。

### 调用范围（隐私）

| 发送 | 不发送 |
|------|--------|
| 发送池内**超长行**原文（每批最多 10 行） | 全文文稿、未超长行 |
| `min_chars`（prompt 最短行长）、`max_chars`（prompt 参考上限） | 用户标识、设备信息 |
| 断句指令（系统提示：语义切分、仅换行不改写） | |

- **批量调用**：每批一次请求，最多 10 行；**不是**全文一次上传
- **不改写**：提示词约束模型只返回切分后的行列表，不润色、不纠错、不增删语义；流水线以句意守恒硬校验兜底
- 响应仅用于替换对应行切分结果，不持久化到 SQLite

### 未配置 / 失败行为

| 场景 | 行为 |
|------|------|
| 未配置或未启用（`llm_enabled=false` / 缺 endpoint/model/密钥） | 跳过步骤 6，超长行进入步骤 8 **标记** |
| 单次 API 调用失败（网络、4xx/5xx，含传输层重试用尽） | 记录日志；该批受影响条目计 1 次质量尝试并回池或放弃 |
| 质检不合格 | 回池返工，直至满 3 次后放弃并标记 |
| 超时 | 见下文传输层重试 |

### 超时与传输层重试（与质量返工分离）

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 单次请求超时 | 30 秒 | MVP **不向用户暴露**超时配置项 |
| 传输层重试 | 最多 1 次 | 仅对网络错误、超时、5xx；不对 4xx 重试；**不计入**「质量返工 3 次」之外的额外语义——传输层用尽仍失败时，才计 1 次质量尝试 |

具体实现可用 `tenacity` 或手写重试；不扩大请求体范围（仍不超过池内当批行）。

### Mock 与测试

- 单元测试通过 **注入 `MockLlmClient`** 验证发送池、批量、质检、返工与放弃
- `MockLlmClient.break_lines` 返回确定性切分结果，不调用网络；可配置「故意不合格」以测返工
- 集成测试可选：标记 `@pytest.mark.integration` 的真实 API 测试，**默认 CI 不运行**

### 与 ADR-004 的边界

| ADR-004 | ADR-005（本文档） |
|---------|-------------------|
| 存 endpoint、model | 如何调用、发什么、发送池、质检、mock、超时 |
| 密钥不入库 | 密钥从 env 读取并用于 OpenAI 客户端 |

## 后果

### 正面

- OpenAI 兼容方案覆盖多数自建/国内网关
- `LlmClient` 协议便于测试与替换实现
- 隐私边界清晰：仅池内超长行出境（每批 ≤10），符合产品定义
- 质检硬门禁降低「未切分 / 无进展 / 改写」直接进入成片的风险；行长只作提示目标，最终超长由步骤 8 标记
- 未配置时核心功能仍可离线使用

### 负面

- 非兼容端点需用户自行提供兼容网关
- 批量 + 返工可能增加单次处理的 API 调用次数与耗时（相对旧「逐行一刀切」）
- 模型切分质量仍依赖提示词；阅读节奏无独立打分器

### 修订说明（相对初版）

| 原约定 | 现约定 |
|--------|--------|
| MVP 默认逐行一次请求 | 发送池批量，每批最多 10 行 |
| 无结果质检 | 句意守恒 + 有效切分 + 有进展硬门禁 |
| LLM 质检同时硬验 min/max 字数 | `min_chars` 用于阻止碎句；`max_chars` 仍语义优先，最终超长由步骤 8 标记 |
| API 失败即保留并标记 | 质量路径最多 3 次尝试后再标记 |
| `break_line(单行)` 为协议主入口 | `break_lines(批次)` 为编排主入口 |
