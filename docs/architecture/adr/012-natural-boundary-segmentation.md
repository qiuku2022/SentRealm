# ADR-012: 基于自然边界的全局规则断句

## 状态

已接受

## 背景

历史流水线把每个被删除标点立即替换为换行，再对超长行按词表贪心切分。真实财经口播稿验证发现两类同时存在的问题：引号、顿号、逗号会制造大量短字幕；`的`、`有` 等单字切点会拆开语法成分。与此同时，没有白名单切点的行仍会超长。调整 `min_chars` 只能在短行和超长标记之间转移问题，无法修复标点硬换行与局部贪心的结构性缺陷。

## 选项

1. 仅提高 `min_chars` 或扩大 `max_chars`：改动小，但标点短行不受影响，且会增加超长标记。
2. 继续使用贪心算法，仅清理词表：可减少部分误切，但引号/逗号仍会提前形成不可逆换行。
3. 将标点转为分级候选，在自然句内全局选择整组切点，并增加短行修复。
4. 默认对全文使用 LLM：语义能力强，但违反本地优先、可选联网与最小上传范围。

## 决策

采用选项 3：

- 原始换行及句号、问号、感叹号为硬边界，形成自然句；
- 逗号、分号、冒号、顿号、破折号、省略号在删除时只记录为分级候选；
- 引号、括号仅删除；未知自定义去除符号默认仅删除；
- 只有超长自然句进入规则断句；候选来源包括标点、英文词界和用户词表；
- 使用动态规划综合边界优先级、行长均衡、短行惩罚、局部超长惩罚和高风险语法切点；
- 无法自然切开的局部段允许保留超长，继续进入 LLM 发送池或最终标记；
- 规则结果在同一自然句内做短行回并，不跨越硬边界；
- `Settings`、HTTP、CLI、MCP 的外部字段结构保持不变，`punctuation_remove` 的语义从“去除并换行”调整为“去除并按内置等级提供边界”。

高风险单字切点从新版出厂词表移除；为兼容已有 SQLite 词表，选择器仍会对这些位置施加高惩罚。LLM 仍只接收规则后超长行，不参与全文重排。

## 后果

### 正面

- 引号不再孤立短词，未超长句中的逗号不再无条件换行；
- 全局选点避免“短头 + 超长尾”的局部贪心结果；
- 规则层可以明确选择“保留并标记”而不是破坏语法；
- 三入口继续复用 `core`，无需数据库或 API schema 迁移；
- 保持无 LLM 时可离线运行。

### 负面

- 规则实现比贪心算法复杂，需要真实稿件回归测试约束评分；
- 为保护语义，竖屏 10 字预设下的超长标记数量可能增加；
- 已有用户会观察到同一稿件重新处理后的分行变化；
- 内置标点等级暂不可由用户分别编辑，若后续确有需求再扩展 Settings schema。
